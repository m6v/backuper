# partback / partrest

Набор быстрых системных утилит на C++17 для блочного резервного копирования и атомарного восстановления разделов дисков под Linux (`ext2`/`ext3`/`ext4`, `NTFS`, `exFAT` и посекторного `raw`/`dd`).

Проект спроектирован как компактная, предсказуемая альтернатива `partclone` для работы в Unix-пайпах (`zstd`, `ssh`, `dd`), интеграции с TUI-интерфейсами (`whiptail`/`dialog` через `--status-fd`) и упаковки в автономные загрузочные Live-системы (DVD-R / USB).

---

## Возможности

* **Единый бинарник `partback` с автоопределением ФС:** автоматически распознаёт тип файловой системы через `libblkid` и выбирает оптимальную стратегию копирования только занятых блоков/кластеров.
* **Универсальный реставратор `partrest`:** восстанавливает образы любых поддерживаемых ФС (включая `raw`), а также умеет проверять целостность архивов без записи на диск (`--verify`).
* **Высокая скорость и I/O Coalescing:** непрерывные диапазоны занятых блоков склеиваются в крупные чанки размером до **4 МБ**, минимизируя системные вызовы `read`/`pread`/`write`/`pwrite`.
* **Двойная защита целостности (`CRC32`):** отдельная контрольная сумма для каждого заголовка (`ImageHeader`, `ChunkHeader`) и для блока данных, а также обязательный маркер `EOF` в конце потока.
* **Атомарная фиксация при восстановлении (Two-Phase Commit):** при восстановлении `partrest` сначала затирает первые 4096 байт раздела (основной суперблок / VBR) и придерживает начальные чанки в ОЗУ, записывая их на диск **только в самом конце** после подтверждения чистого `EOF` и `fsync()`. Прерванный при сбое питания процесс никогда не оставит на диске недописанную ФС, способную смонтироваться.
* **Системная безопасность:** проверка `/proc/mounts` (с разрешением симлинков `/dev/disk/by-*`) и установка блокировок ядра `flock` (`LOCK_SH` при бэкапе, `LOCK_EX` при восстановлении) для защиты от гонок с `systemd-udevd` и параллельными процессами.
* **Машиночитаемый прогресс-бар:** вывод процентов и средней скорости (МБ/с) в отдельный файловый дескриптор (`--status-fd N`) в формате `whiptail`/`dialog` без смешивания с диагностикой и ошибками в `stderr`.

## Архитектура проекта

Проект построен на модульной архитектуре без глобального состояния и с детерминированным управлением ресурсами (RAII).

### Структура файлов

| Файл | Назначение |
| :--- | :--- |
| `sysutil.hpp` | Системные обертки ОС: `UniqueFd` (RAII над `int fd` с поддержкой `flock`), `io_exact` (цикл гарантированного I/O с обработкой `EINTR`), `ensure_not_mounted` (чтение `/proc/mounts`), парсер CLI `parse_cli_args`. |
| `progress.hpp` | Класс `ProgressReporter`: расчёт процента выполнения и средней скорости (МБ/с), вывод в `--status-fd` не чаще раза в 250 мс. |
| `partimg.hpp` | Спецификация бинарного контейнера `EXTIMAGE` (версия 3): структуры `ImageHeader`, `ChunkHeader` и вычисление `CRC32` через `zlib`. |
| `imgwriter.hpp` | Класс `ImageWriter`: потоковая упаковка занятых блоков, склейка соседних блоков в чанки до 4 МБ, нарезка произвольных диапазонов (`write_range`) и запись финального `EOF`. |
| `backuper.hpp` | Базовый абстрактный класс `VolumeBackuper` (паттерн *Template Method*: проверяет монтирование, ставит `LOCK_SH` и вызывает виртуальный `do_backup`), объявления `detect_filesystem` и фабрики `create_backuper`. |
| `backuper_extfs.hpp/.cpp` | Стратегия `ExtfsBackuper` (`ext2/3/4` через `libext2fs`). Проверяет флаг грязного журнала `EXT3_FEATURE_INCOMPAT_RECOVER`. |
| `backuper_ntfs.hpp/.cpp` | Стратегия `NtfsBackuper` (`NTFS` через `libntfs-3g`). Читает `$Bitmap`, запрещает бэкап при `VOLUME_IS_DIRTY` (гибернация / Fast Startup Windows), принудительно включает последний граничный блок раздела с резервным загрузочным сектором (`Alternate VBR`). |
| `backuper_exfat.hpp/.cpp` | Стратегия `ExfatBackuper` (прямой парсинг VBR, FAT и записи `0x81 Allocation Bitmap` в корневом каталоге без внешних библиотек). Проверяет флаг `VolumeDirty`. |
| `backuper_raw.hpp/.cpp` | Стратегия `RawBackuper` (фолбэк для `vfat`/ESP, `xfs`, `btrfs`, `swap` и произвольных файлов). Автовыбор размера блока: `4096`, `512` или `1` байт. |
| `partback.cpp` | Точка входа `partback`: автоопределение ФС через `libblkid` и запуск выбранного полиморфного бэкапера. |
| `partrest.cpp` | Точка входа `partrest`: проверка архива (`--verify`) и двухфазное атомарное восстановление. |
| `autotests.sh` | Сквозные интеграционные тесты на loop-образах (`ext4` с фрагментацией, `vfat`, `ntfs`, `exfat`, негативный тест битого `CRC32`). |

## Спецификация бинарного формата `EXTIMAGE` (v3)

Все многобайтовые поля хранятся в Little-Endian (нативный порядок байт x86_64/ARM64), структуры упакованы с выравниванием `#pragma pack(push, 1)`.

### 1. Заголовок образа (`ImageHeader` — 36 байт)

| Смещение | Размер | Поле | Описание |
| :--- | :--- | :--- | :--- |
| `0` | 8 | `magic` | Сигнатура `"EXTIMAGE"` |
| `8` | 4 | `version` | Версия протокола (`3`) |
| `12` | 4 | `block_size` | Размер логического блока в байтах (`4096`, `512`, `1` и др.) |
| `16` | 8 | `total_blocks` | Общее число блоков в исходном разделе |
| `24` | 8 | `used_blocks` | Число занятых блоков (используется для расчёта прогресса) |
| `32` | 4 | `header_crc32` | `CRC32` первых 32 байт заголовка |

### 2. Поток чанков (`ChunkHeader` — 20 байт + полезные данные)
После `ImageHeader` идёт последовательность чанков до маркера конца потока:

| Смещение | Размер | Поле | Описание |
| :--- | :--- | :--- | :--- |
| `0` | 8 | `start_block` | Индекс начального блока диапазона |
| `8` | 4 | `block_count` | Число блоков в чанке (`0` означает штатный маркер `EOF`) |
| `12` | 4 | `header_crc32` | `CRC32` полей `start_block` и `block_count` (первые 12 байт) |
| `16` | 4 | `data_crc32` | `CRC32` массива данных размером `block_count * block_size` байт |
| `20` | `N` | `data` | Несжатые блоки данных (отсутствуют, если `block_count == 0`) |

## Сборка и зависимости

### Зависимости (Debian / Ubuntu / Astra Linux)
```bash
sudo apt update
sudo apt install g++ make zlib1g-dev libblkid-dev uuid-dev libext2fs-dev ntfs-3g-dev
# Для запуска полного набора автотестов также желательны:
sudo apt install zstd dosfstools ntfs-3g exfatprogs
```

### Команды сборки
* **Обычная динамическая сборка:**
  ```bash
  make
  ```
* **Автономная статическая сборка (для Live-DVD / Rescue USB):**
  ```bash
  make static
  ```
* **Установка в систему (`/usr/local/bin`):**
  ```bash
  sudo make install
  ```
* **Запуск сквозных автотестов:**
  ```bash
  make test
  ```

## Примеры использования

### 1. Создание сжатого резервного образа (в потоке через `zstd`)
```bash
partback /dev/nvme0n1p2 - | zstd -T0 -o root_backup.img.zst
```
*(Для эталонного Golden Image на DVD-R рекомендуется максимальное сжатие `zstd -19 -T0` — скорость последующей распаковки при этом не снижается.)*

### 2. Проверка целостности архива без записи на диск (`--verify`)
```bash
zstd -dc -q root_backup.img.zst | partrest --verify -
```

### 3. Восстановление на целевой раздел
```bash
zstd -dc -q root_backup.img.zst | partrest - /dev/nvme0n1p2
```

### 4. Интеграция с `whiptail` в Bash-скриптах (`--status-fd 3`)
```bash
partback --status-fd 3 /dev/sda2 - 2>/tmp/err.log \
    3> >(whiptail --title "Резервное копирование" --gauge "Подготовка..." 9 65 0 > /dev/tty) | \
    zstd -T0 -f -q -o /mnt/usb/sda2.img.zst
```

## Заметки для дальнейшей доработки (Контекст для ИИ-ассистента)

При продолжении работы над проектом учитывать следующие архитектурные соглашения:
1. **Изоляция C-заголовков:** заголовки `<ext2fs/ext2fs.h>` и `<ntfs-3g/...>` (с `extern "C"`) должны подключаться **только** внутри своих `.cpp`-файлов (`backuper_extfs.cpp`, `backuper_ntfs.cpp`) и строго **после** заголовков стандартной библиотеки C++, так как они определяют конфликтующие C-макросы (`clamp`, `min`, `max`).
2. **Расширение поддержкой новых ФС:** чтобы добавить новую файловую систему (например, `F2FS`), достаточно унаследовать класс от `VolumeBackuper` (реализовав `do_backup`), добавить ветку в `create_backuper()` в `partback.cpp` и подключить объектный файл в `Makefile`. Формат `EXTIMAGE` и код `partrest` менять не требуется.
3. **Инвариант безопасности `partrest`:** первые `max(4096, block_size)` байт раздела всегда затираются в начале восстановления и записываются из `deferred_head_chunks` только после получения `clean_eof` и `fsync()`.
4. **Особенности NTFS:** `NtfsBackuper` намеренно добавляет `+1` блок к `vol->nr_clusters` и дочитывает его через `::pread`, чтобы сохранить резервный загрузочный сектор (`Alternate VBR`), расположенный в последнем секторе раздела за пределами области кластеров.
