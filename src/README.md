# Аналог partclone.extfs

`backpart.extfs` и `restpart.extfs` — это пара консольных системных утилит для быстрого посекторного (блочного) резервного копирования и восстановления разделов ext2/ext3/ext4 в Linux, работающие напрямую с низкоуровневой картой занятости блоков файловой системы.

## Алгоритм создания резервной копии

1. Проверка безопасности и целостности исходного раздела (перед началом работы утилита проверяет через системную библиотеку `libext2fs`, не смонтирован ли исходный раздел в режиме записи (rw), если раздел используется системой или имеет невосстановленный журнал сбоев, работа немедленно прерывается, чтобы не создать несогласованную копию).
2. Анализ битовой карты (block bitmap) (программа читает суперблок и загружает в память карту занятых блоков файловой системы, по ней подсчитывается точное количество полезных блоков (для расчета прогресса), а все свободные блоки диска полностью игнорируются).
3. Склейка блоков в крупные чанки (I/O Coalescing) (чтобы не замедлять диск многочисленными мелкими операциями чтения по 4 КБ, pbackup объединяет подряд идущие занятые блоки в единые непрерывные фрагменты (чанки) размером до 4 МБ и считывает их за один системный вызов).
4. Формирование потокового контейнера с контролем целостности (каждый прочитанный чанк снабжается компактным заголовком (начальный номер блока, количество блоков, контрольные суммы CRC32 отдельно для заголовка и для полезных данных) и отправляется в файл или стандартный поток вывода (stdout) (для сжатия «на лету» внешними архиваторами (zstd, pigz) или передачи по сети через ssh).
5. Запись по окончанию копирования всех блоков специального логического маркера завершения потока (финального заголовока с нулевым количеством блоков (block_count = 0)), позволяюшего при восстановлении отличить полноценный архив от файла, оборванного из-за сбоя сети или нехватки места.

## Алгоритм восстановления

1. Защита от перезаписи рабочих дисков и опечаток (перед открытием целевого устройства утилита проверяет, что путь в /dev/ действительно указывает на существующее блочное устройство (защита от случайного создания гигантского файла в ОЗУ при опечатке в имени диска), что целевой раздел полностью размонтирован, а его физический объем не меньше размера исходной файловой системы.
2. Потоковая верификация (CRC32) (утилита читает поток из файла или стандартного входа (stdin — например, распакованный поток от zstd -dc), до записи на диск для каждого чанка сверяются контрольные суммы заголовка и данных, при малейшем битовом сбое или обрыве архива запись прерывается, предотвращая порчу данных на диске, если входной поток неожиданно закроется (системный EOF) до получения логического маркера завершения (block_count = 0), утилита зафиксирует обрыв архива и сообщит об ошибке.
3. Прямая адресная запись (pwrite) (проверенные блоки данных записываются строго по своим исходным смещениям на целевом разделе, а свободные участки пропускаются, после получения специального маркера штатного завершения потока (EOF) вызывается fsync() для гарантированного сброса кэша ядра на физический носитель).

## Тестирование
```
cd /tmp
mkdir -p src dst
# Здесь в зависимости от типа раздела делаем бэкап src.img и восстановление в dst.img
mount -o loop,ro src.img src
mount -o loop,ro dst.img dst
diff -rq --no-dereference src dst
umount src
umount dst
```

## Использование
Утилиты не имеют графического интерефйса и не одеспечивают сжатия.
- сжатие делегируется специализированным внешним архиваторам через Unix-пайпы.
- интерактивный прогресс (проценты, обработанные мегабайты и текущая скорость в МБ/с) передается через отдельный файловый дескриптор (--progress-fd) напрямую в консольные диалоги вроде whiptail или dialog.

Бэкап файла или раздела с образом
```bash
partback.extfs --status-fd 3 /tmp/src.img - 2>/dev/null 3> >(whiptail --title "Backup" --gauge "Инициализация..." 9 65 0 > /dev/tty) | zstd -T0 -f -q -o backup.img
```

Восстановление файла или раздела из образа
```bash
zstd -dc -q backup.img | partrest.all --status-fd 3 - /tmp/dst.img 2>/dev/null 3> >(whiptail --title "Restore" --gauge "Инициализация..." 9 65 0 > /dev/tty)
```

Проверка целостности образа
```
zstd -dc -q backup.img | partrest.all --verify -
```

## Бэкап ESP

Бэкап ESP с прогресс-баром
```
# Размер раздела в байтах для pv (-s)
ESP_SIZE=$(blockdev --getsize64 /dev/sda1)

dd if=/dev/sda1 bs=4M status=none \
    | pv -n -s "$ESP_SIZE" 2> >(whiptail --title "Backup ESP" --gauge "Копирование EFI-раздела..." 8 60 0 > /dev/tty) \
    | zstd -T0 -f -q -o esp.img.zst
```

Восстановление ESP с прогресс-баром
```
ESP_SIZE=$(blockdev --getsize64 /dev/sda1)

zstd -dc -q esp.img.zst \
    | pv -n -s "$ESP_SIZE" 2> >(whiptail --title "Restore ESP" --gauge "Восстановление EFI-раздела..." 8 60 0 > /dev/tty) \
    | dd of=/dev/sda1 bs=4M conv=fsync status=none
```
>Если утилита pv не установлена в системе, её можно заменить на обычное окно ожидания whiptail --infobox "Копирование EFI-раздела..." 7 50, так как 200–500 МБ копируются меньше чем за секунду
